# Retention improvements — 2026-11-24

This is the standalone half of the cumulative metadata/reference/lineage/reviewed-cleanup checkpoint. The companion extension is LumiSwarm Studio. No Lumiverse core or Swarm source is changed.

## Distinct creation tags

Schema 1 remains a flat string map. Existing stages remain supported. New jobs distinguish `quick_create`, `inline_inpaint_variant`, `inline_upscale_result` and `inline_background_removed`, alongside `general_generation`, `inline_illustration` and the ordinary processing stages. New metadata also records `studio_surface`: main_studio, quick_create, inline or expression. Lumi routes Quick Create/miniplayer, main Studio, inline region edits, inline finalization/enhancement, toolkit enhancement and expression processing to their actual contexts. Standalone reads these tags and exposes all eleven exact stages independently in each origin's metadata-stage settings. Chain rules normalize inline processing to its ordinary processing kind, without conflating the explicit stage selections. Old saved files are not rewritten or retroactively attributed.

## Branch choices

Inspect → Review versions offers Follow policy / Keep this branch / Discard · review required on each resolved saved node. Choices persist in localStorage under `studio-branches-v1:` plus the exact Swarm server/user/output-root scope. They match full asset, producer, pipeline and physical path identities. A branch choice covers that node and its descendants. Siblings and shared ancestors retain their own rules. A keep on any resolved ancestor wins over a descendant discard. Missing/cyclic/ambiguous ancestry cannot grant a discard override. A corrupt/unreadable branch ledger blocks cleanup reference completeness.

Keep prevents both manual and automatic Vacuum selection. Discard makes that branch reviewable even at a leaf or within the grace period; it cannot override favorites, known direct references, active workspaces, exclusions, active jobs, incomplete history or unreadable file headers. It is recorded as a manual override in the exact-path review/log and is never included in automatic cleanup. Removing a choice restores policy. Branch changes invalidate prepared approvals. These choices are standalone retention state; the read-only Lumi relay does not mutate or sync them into Lumiverse.

## Optional idle execution

What to keep → Clean repeats while Studio is idle is OFF by default and scoped to the current connection. It unlocks after a fully confirmed reviewed run under the same policy and branch choices. Existing successful records normalize an absent/empty branch list equivalently. Server identity and recycle mode must still match that evidence before execution. An uncertain/unfinished/failed automatic run requires a newer successful reviewed run before re-enabling.

Studio checks once a minute while open and visible. A run requires at least a minute without keyboard/pointer activity, thirty minutes since the previous attempt, idle Swarm/Studio jobs, no scan/sync/cleanup, and a closed Vacuum dialog. There is no OS scheduler or execution when Studio is closed. Maximum batch size is configurable as 5, 10 or 20 (default 10).

The automatic set is the intersection of the current candidate policy and conservative superseded-chain eligibility, with at least seven days of age. No untagged/ambiguous files, main-generation branch ends, surviving branch ends, explicit discard overrides, recent sources or protected files enter it. Explicit metadata-stage selection of a final does not authorize automatic deletion of that final. Actual replacement headers, current identity, favorites, local project audit, configured live/manual reference freshness, policy and branch decisions are rechecked before every file and at the pre-send boundary. The existing frozen-plan engine, write-ahead audit and same-browser lease execute the bounded set. Automation settings are rechecked before sending; turning them off stops future requests. An already-sent request cannot be retracted. Uncertainty, skipped/check failures or audit persistence failure pauses execution. Swarm recycling remains the server's setting; automation does not promise recovery or add a recycle setting.

Results labels automatic runs and retains the per-file history/export. The implementation does not enable this feature in any real user profile, perform a real cleanup, or grant authorization to delete arbitrary files. Only fixture APIs were mutated during validation.
